# 監測可行性檢核工具 說明 v1

**日期**：2026-08-22
**檔案**：`工具_監測可行性檢核.html`（單一自含檔，離線可開）

---

## 壹、這個工具解決什麼

任何人想在減藥期間用動態訊號做早期預警，第一個要回答的問題是
「我手上這種監測密度，有沒有機會看到訊號」。

目前沒有人能事先回答。實務上的做法是先申請資料或先做研究，
跑到最後才發現抽血密度不足以估計自相關，那時已經花掉數個月到數年。

本工具把這個問題變成查表：輸入監測長度、取樣間隔、量測誤差，
直接得到判定。使用者是任何要設計監測研究的人。

---

## 貳、輸出的兩軸，以及為什麼不能只看一軸

| 軸 | 問題 | 衡量方式 |
|---|---|---|
| 偵測軸 | 能不能看出「有事在變」 | 分岔翻轉組相對穩定未發作組的 AUC |
| 特異軸 | 能不能分辨「真的失去穩定性」與「只是雜訊變大」 | 分岔翻轉組相對雜訊放大組的 AUC |

綜合判定取兩軸較差者。理由是一個測得到卻分不出真假的指標，
在臨床上只會製造假警報，而假警報的成本由病人承擔。

特異軸低於 0.50 有特殊意義：代表雜訊假象的訊號比真訊號更強。

---

## 參、格點結果（本工具的主要發現）

96 個格點，有效 52 個（其餘因資料點不足無法估計）。

| 指標 | 結果 |
|---|---|
| 偵測軸最高 AUC | 0.76 |
| 特異軸最高 AUC | 0.45 |
| 特異軸中位 AUC | 0.28 |
| 特異軸低於 0.50 的格數 | **52 / 52，全部** |

**結論一：訊號存在。** 在監測 730 天、每 3 至 14 天一次、誤差不超過生理波動一半的條件下，
偵測軸 AUC 可達 0.73 至 0.76，明顯優於隨機。也就是說「有事在變」是看得出來的。

**結論二：但分不出真假，而且加密取樣救不了。**
全部 52 個有效格點的特異軸 AUC 都低於 0.50，中位僅 0.28。
這代表單純變異度增大所產生的訊號，比真正的穩定性喪失更強。
從最疏的每 90 天到最密的每 3 天、從最大誤差到零誤差，這個結論都沒有改變。

**結論三：因此瓶頸不是資料密度，是指標本身。**
這一點推翻了本研究原先的預期。原先假設主要限制是取樣密度不足，
所以病人端高頻資料會是解方；實際結果顯示，即使給到每三天一次、零量測誤差，
自相關與變異度的組合仍然無法區分兩種機制。
要解決的不是多測幾次，而是需要一個與變異度無關的第二個區辨資訊。

## 肆、方法

| 項目 | 設定 |
|---|---|
| 生成機制 | 分岔翻轉、穩定未發作、雜訊放大，各 250 位 |
| 評分時點 | 監測期末評分一次（地標式），避免反覆評估造成的多重比較 |
| 評分內容 | 滾動一階自相關與滾動標準差，各取與時間的 Kendall tau，兩者平均 |
| 自相關定義 | 去線性趨勢後之自協方差型 lag-1 自相關 |
| 視窗 | 目標 60 至 180 天，並確保至少 8 點；不足者標為資料量不足 |
| 判定門檻 | 偵測軸 0.70／0.60；特異軸 0.65／0.55。門檻於計算前寫定 |

地標式評分是相對於先前警報規則版本的重要修正。
先前以累積 Kendall tau 反覆評估，等於多重比較，
使穩定序列的最大值偏高、門檻被推到極端值；改為期末評分一次後此問題消失。

---

## 伍、限制

1. 三種生成機制之外，尚未納入隨機越障、外生衝擊、連續惡化與症狀驅動取樣。
   完整版應含六種機制，屆時特異軸可能更差。
2. 各機制的參數為本研究設定，非文獻錨定；四項待抽取參數尚未補齊。
3. AUC 為模擬設定下的區辨力，不等於臨床效能。
4. 未納入治療悖論——真實世界中檢驗異常會觸發加藥，改變後續軌跡。
5. 本工具查的是查表結果，不做即時模擬；改變模型參數需重新產生格點。

## 陸、使用方式

以瀏覽器開啟 `工具_監測可行性檢核.html`，離線可用，不發任何網路請求，不寫入任何儲存。

整體地圖可直接點選任一格帶入條件。每格顯示「偵測軸 AUC ／ 特異軸 AUC」。
