這份研究目前有兩條並行的線，**架構不一致**。依鐵則 7（衝突要攤開講、禁止混合寫法），
這裡不做平均、不寫「兩邊都照顧到」的折衷版，而是把差異逐項列出、指出哪些是實質衝突、
給一個明確的收斂建議，並標出哪些必須由你裁決。

## 肆、三個實質衝突（不是措辭差異）

### 衝突一：共變異數算在哪一層——這是最大的一個

計畫線的 [交叉動差](../05_概念筆記/交叉動差.md) 是**同一位病人**在多次同日成套之間的通道共變，
[誤差免疫](../05_概念筆記/誤差免疫.md) 之所以成立，靠的正是「各通道的化驗誤差彼此獨立，
在交叉共變異數中期望值為零」。這個性質作用在**該病人自己的**共變上。

程式線的 Ψ 是在**整個世代**的指標共變矩陣上用非對角 ULS 擬合的；
而每一位病人的歸因是把他**單次就診**的指標向量 x 對固定 Λ 做 NNLS。

後果有三個，都需要正視：

1. **資料前提差一個數量級。** 計畫線需要每人 ≥ 8 次同日成套；程式線一次就能跑。
   這決定了誰能被納入——[同日多通道](../05_概念筆記/同日多通道.md) 已經寫明結構性盲點：
   要有 8 次以上成套代表這人已在系統內長期追蹤，**急性表現者（RPGN、突發腎病症候群）
   往往數週內就切片，序列不足會被排除——而急性正是診斷最急迫的時候**。
   程式線沒有這個限制，而且它的 L2 硬分流專門處理的就是抗 GBM 與 ANCA-GN 這類時效性個案。
   **這一點上兩條線是互補的，不是誰對誰錯。**

2. **誤差免疫在程式線的逐人步驟上不成立。** 非對角只在世代層級的 Ψ 擬合用到；
   逐人 NNLS 吃的是含量測誤差的 x。程式線自己也沒宣稱有誤差免疫（它宣稱的是
   「Θ 在非對角擬合時消掉」與「擬合優度變成證偽測試」），但**兩條線的文件都用了「只用非對角」
   這個說法指涉不同的東西**，混講會出事。

3. CGRD 第一階段第一個彙總計數（切片前 365 天有 ≥ 8 次同日成套者的占比，
   門檻 < 20% 則放寬窗至 730 天）**只約束計畫線**。若最後走程式線的橫斷面版本，這個門檻不適用。

### 衝突二：狼瘡是閘門還是標的

v9 的核心修正是「狼瘡是閘門不是標的」，並由此得到 [通道消耗規則](../05_概念筆記/通道消耗規則.md)。
程式線把免疫介導腎絲球腎炎（含狼瘡增生型）當成 L3 二元的陽性集合，
而且 ANA 效價、C3、C4 都是模型特徵——**這正是通道消耗規則禁止的**。

程式線並非沒有處理循環性，它的解法是**換標籤**：用腎切片組織型態而不是臨床診斷名。
這確實切斷了「用血清學預測用血清學下的診斷」那條循環。

**但兩個解法不會自動相容**：v9 的解法把狼瘡血清學整條封存，程式線的解法保留它們當特徵。
必須擇一，不能兩個都寫。

### 衝突三：C4 的方向

計畫線把「C4 在古典途徑與替代途徑之間負載異號」列為
[負載矩陣錨定表](../03_公式與方法/負載矩陣錨定表%20v1.md) 的第一項修改，
理由是 Tringali 2024 的「低 C3 且高 C4」——這也是 [補體四象限](../05_概念筆記/補體四象限.md) 第一格的來源。

程式線的 `c4_low` 在三個驅動上的載荷是 [0.80, 0.05, 0.00]，全部非負。
**這不是參數填錯，是結構上放不下**：程式線根本沒有「替代／凝集素途徑」這個驅動，
它的 D1 免疫沉積把古典與替代合在一起。所以補體四象限在現行 Λ 下無法表達。

## 伍、三個一致的地方（互相驗證，見 [數據總表](數據總表.md) 參節）

自由估計負載不可行、只用非對角有效、逐人標準化該禁、洩漏基準要先建——
四件事兩條線用**不同資料、不同統計量**各測了一次，結論方向一致。
這提高了「這些性質是結構性的、不是某個生成器的巧合」的可信度。

一個必須注意的細節：**「禁逐人標準化」兩線的理由不同**。
計畫線的理由是誤差免疫失效（逐人 z 後比例重新含 σ）；
程式線實測發現橫斷面逐人 z 只掉 AUROC 0.008，真正的依據是**縱向洩漏**（0.902／0.719／0.563）。
兩個理由都成立，寫論文時要分開講，混為一談會失去說服力。

## 陸、收斂建議

**建議：以 v9 的 G0–G5 為骨架，把程式線的紀律層與安全機制整批搬過去。**

理由：v9 是後出的、且是使用者親自指出的修正，它解掉的循環性漏洞原本被列為致命級；
而程式線的價值不在架構，在它**真的跑起來了**，並且做出了 v9 目前完全沒有的幾件事。

具體怎麼搬：

| v9 的層 | 從程式線搬什麼 |
|---|---|
| G0 資料品質 | L1 的棄權機制（缺值／單位錯置／不可能值／時間窗過期 → 棄權不猜） |
| G1 狼瘡閘門 | 「**未回覆 ≠ 陰性**」的兩欄位設計——這是 G1 最容易犯的靜默錯誤 |
| G2 決定性標記 | L2 的純 if-else 硬分流表（`params/deterministic.json` 可整份沿用），以及**單向安全否決** |
| G3 補體四象限 | 無可搬（程式線未實作）；這是 v9 必須自己補的主要工作 |
| G4 殘餘軸 | L4 的固定 Λ ＋ NNLS 求解程式碼可沿用，但 **Λ 要換成 v9 的三驅動並補 PMID** |
| G5 混合旗標 | L5 旗標邏輯；秩一殘差仍須另補（N ≥ 60 子群） |
| 紀律層（跨層） | M0 洩漏基準、六道閘門的 `run.py` 骨架、參數雜湊與 seed 可重現性設計 |
| 產品層 | 安全終點（時效性漏判率上限）＋樣本量由安全終點決定的算法；單檔離線介面與黃金案例自我校驗 |

**不建議的做法**：把 L3 的二元免疫判定原樣留著再加一個 G1 狼瘡閘門。
那會變成「先排除狼瘡，然後再判斷是不是免疫性」——第二步的陽性集合裡最大的一塊剛好被第一步排掉了，
是一個內部矛盾的管線。要嘛 D3 復活（推翻 v9），要嘛 L3 改成 G1 之後的殘餘 rule-out（重新定義陽性集合）。

## 柒、需要你裁決的

這幾項無法從程式或文獻推出來，必須由你決定：

1. **架構擇一**：v9 的 G0–G5，還是程式線的 L1–L5？（建議 G0–G5，理由如上）
2. **共變異數的層級**：人內縱向（需 ≥8 次同日成套，排除急性個案）還是人間橫斷（單次可跑）？
   或者**分成兩個產品**——橫斷面版給急性、縱向版給長期追蹤者？
3. **狼瘡血清學**：封存（v9 通道消耗規則）還是保留為特徵（程式線＋組織型態標籤）？
4. **驅動定義**：替代免疫／代謝／血流動力（v9），還是免疫沉積／壞死內皮／足細胞屏障（程式線）？
   前者對得上補體四象限與文獻錨定表，後者對得上時效性個案的處理。
5. **PR #606 怎麼處理**：依 v9 改寫後再合併、先合併保存現狀、還是就這樣停在 draft？

第 5 項會影響前四項的工作量，建議先答。其餘待裁決事項見 [待裁決事項總表](待裁決事項總表.md)。
