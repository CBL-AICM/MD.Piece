# 第零部　工作規則（全程適用）

1. 規格未涵蓋之處先問，不要自行假設。
2. 任何數值都必須有出處。無出處者留 `null`，程式啟動時列印警告，**不得為了讓程式跑起來而自行填值**。
3. 看過結果之後不得回頭調整參數。認為某設定不合理時提出，由我裁決。
4. 若某個結果好得異常，**主動指出它可能只是反映生成器的設定或資訊洩漏**。本專案已有兩次洩漏警報的實例。
5. 假設檢定一律雙尾。
6. 禁止呼叫 `np.random` 全域介面；亂數一律經 `seeding.module_rng(name, seed)`。
7. 每個模組至少一個單元測試，且測試必須能單獨執行。
8. **禁止逐人標準化**（見第二部之四）。此為本專案的硬性禁令，違反會使核心性質失效。
9. **M0 必須先於 M2 建立並定版**。順序錯誤會使洩漏評估失去意義。

# 第一部　研究內容（先讀懂再動手）

## 一之一　問題

病人已經有腎炎，問題是什麼造成的。腎切片是唯一標準答案，但它是侵入性檢查。本研究問：用切片前既有的常規檢驗序列，能不能先判斷病因，尤其能不能把狼瘡腎炎分出或排除。

## 一之二　為什麼單點檢驗不夠

Chedid 2020：87 位低量蛋白尿的狼瘡病人接受切片，低 C3、低 C4、抗雙股 DNA 在單變量迴歸有效，**多變量模型全部失效**。所以問題不是要不要用這些檢驗，而是有沒有別的讀法。

## 一之三　核心想法

每一項檢驗都是同一個潛在腎臟活動度 x 的有雜訊倒影：

　　y_k(t) ＝ l_k · x(t) ＋ ε_k(t)

不同的病用不同的方式拉動這組檢驗——這個「方式」就是負載向量 l 的方向。要估的是方向不是大小。

## 一之四　為什麼[交叉動差](../05_%E6%A6%82%E5%BF%B5%E7%AD%86%E8%A8%98/%E4%BA%A4%E5%8F%89%E5%8B%95%E5%B7%AE.md)可以估出方向

各通道的化驗誤差彼此獨立（尿液比濁法的誤差不知道血清免疫比濁法的誤差是多少），所以：

　　Cov(y_a, y_b) ＝ l_a·l_b·Var(x) ＋ 0 ＋ 0 ＋ 0

用任一第三通道 c 當支點相除，l_c 與 Var(x) 全部約掉：

　　**l_a / l_b ＝ C_ac / C_bc**

誤差完全不進入。這是全案的數學核心。

## 一之五　已知的三個邊界（不要試圖突破，要在設計中避開）

| 邊界 | 內容 |
|---|---|
| 逐人精確估計不可行 | 分母帶雜訊的比值有系統性向零偏誤；N＝8 時中位估計 0.52（真值 1.667） |
| 分類可行 | 因為分類只需保留排序，不需無偏估計；N＝12 → 0.79、34 → 0.87、60 → 0.92 |
| [秩一殘差](../05_%E6%A6%82%E5%BF%B5%E7%AD%86%E8%A8%98/%E7%A7%A9%E4%B8%80%E6%AE%98%E5%B7%AE.md)需大樣本 | N ＜ 34 時區辨 AUC ≈ 0.50；**僅於 N ≥ 60 啟用** |

# 第二部　模型核心（後端）

## 二之一　專案結構

```
nephro_fingerprint/
├─ config/
│  ├─ channels.yaml          # 通道定義、方向調和、A/B/C 配對等級
│  ├─ etiologies.yaml        # 各病因之負載向量與節奏（缺者 null）
│  └─ analysis.yaml          # 窗長、門檻、隨機種子
├─ src/
│  ├─ seeding.py             # module_rng，唯一亂數入口
│  ├─ generator.py           # 多病因合成世代
│  ├─ features.py            # 指紋計算八步
│  ├─ models.py              # M0/M1/M2/M3
│  ├─ evaluate.py            # 排除試驗指標、混淆矩陣、bootstrap
│  └─ gates.py               # 四道閘門
├─ tests/                    # 每模組一支，可單獨執行
├─ outputs/
│  ├─ results.json           # 唯一資料契約，前端只讀這個
│  └─ figures/
└─ run_all.py
```

## 二之二　生成器（`generator.py`）

每位合成病人：

1. 依指定病因取負載向量 `l`（自 `etiologies.yaml`，缺值 null 時該病因不生成並列印警告）。
2. 生成潛在過程 `x(t)`：OU 過程，時間常數依病因（節奏差異本身即為特徵）。
3. 依實際回診型態抽取觀察時點（**不等距**，且允許症狀驅動加密——這是要被檢驗的偏誤，不是要避開的麻煩）。
4. 各通道獨立加誤差 `ε_k`，各通道 σ_k 不同。
5. 輸出：觀察值矩陣、真實負載向量、真實病因標籤、真實 N。

必備對照組：

| 組 | 內容 | 檢驗目的 |
|---|---|---|
| 純雜訊 | 無潛在過程，只有各通道獨立雜訊 | 零信號檢查，必須回到隨機水準 |
| 單通道誤差放大 | 一條通道 σ 變大，負載不變 | 指紋不應改變 |
| 混合病因 | 兩個潛在過程 | 秩一殘差之正對照 |
| 穩定病人 | Var(x) ≈ 0 | 必須被標記為不可估計，不得給值 |

## 二之三　指紋計算八步（`features.py`）

| 步 | 動作 | 注意事項 |
|---|---|---|
| 1 | 界定觀察窗 | 主要切片日前 365 天；敏感度 180／730 |
| 2 | 找同日成套組 | 嚴格：同就診序號且採檢時間戳差 ≤ 4 小時；無時間戳退為同日曆日並標記等級 |
| 3 | 方向調和 | C3、C4 乘 −1 |
| 4 | 標準化 | **僅用全世代分布**之中位數與中位數絕對離差 |
| 5 | 變異門檻檢查 | 低於門檻之通道標記不可估計，不進入配對；全數不可估計者列入「無訊號組」 |
| 6 | 共變異數矩陣 | **只保留非對角元素**；對角線含 σ，一律不使用 |
| 7 | 負載比例與指紋 | 每對 (a,b) 以所有合格第三通道 c 算 C_ac/C_bc，取**中位數**；參考通道取最常有者 |
| 8 | 次要特徵 | λ（多個 Δ，長 Δ 較穩）；領先落後不對稱；秩一殘差 R（**僅 N ≥ 60**）；記錄 N 與可用配對數 |

## 二之四　硬性禁令

```python
# 錯誤示範 —— 絕對不可以
Z = (Y - Y.mean(0)) / Y.std(0)     # 逐人標準化

# 為什麼：z 轉換後 l'_k = l_k / sqrt(l_k^2 Var(x) + sigma_k^2)
# 比例 l'_a/l'_b 重新含有 sigma，誤差免疫失效，且跨病人不可比。
```

在 `features.py` 加入執行期斷言：若偵測到輸入矩陣各欄標準差皆約等於 1，拋出例外並提示本條。

## 二之五　四個模型（`models.py`）

| 模型 | 特徵 | 角色 | 建立順序 |
|---|---|---|---|
| M0 | **僅「哪些檢驗被開立」之指示變數** | 洩漏上界 | **第一** |
| M1 | 窗內最後一次各通道數值 | 臨床基準（Chedid 已證明會失效） | 第二 |
| M2 | 指紋向量 ＋ 節奏 ＋ 領先落後（＋R 若 N 足） | 主模型 | 第三 |
| M3 | M2 但排除疾病特異血清學 | 主要價值主張 | 第四 |

分類器用正則化邏輯迴歸（可解釋、樣本效率高、係數方向可與文獻錨定之負載型態對照）。非線性方法僅列次要且須報告可解釋性代價。

**判定**：M2 未顯著超越 M0 → 停止，報告「區辨力來自檢驗開立型態而非生理訊號」。

## 二之六　四道閘門（`gates.py`，階段一出口）

| 閘門 | 檢查 | 通過條件 |
|---|---|---|
| G1 零信號 | 純雜訊組跑完整流程 | 分類表現回到隨機水準 |
| G2 洩漏 | 特徵是否用到真實病因標籤、真實負載或未來資訊 | 禁用變項全數排除；以人工注入標籤測試應報錯 |
| G3 誤差不變性 | 單通道誤差放大組之指紋 | 與原組無顯著差異 |
| G4 標準化 | 對逐人標準化資料執行 | 應拋出例外 |

四個閘門的數值要回報，不是回報「通過」兩個字。

# 第三部　前端處理

## 三之一　定位

前端不是儀表板，是**判讀輔助**。它要回答三件事：這個病人的指紋長什麼樣、它離各病因的參考指紋多遠、這個判讀可不可信。

沿用既有 `可行性檢核工具/工具_監測可行性檢核.html` 的單檔骨架（無外部相依、直接開啟即可用）。

## 三之二　資料契約

前端**只讀** `outputs/results.json`，不做任何計算。契約如下：

## 三之三　四個畫面

| 畫面 | 內容 | 硬規則 |
|---|---|---|
| 一、指紋比對 | 雷達圖：本人指紋疊在各病因參考指紋上，附信賴區間帶 | 參考指紋若 `source` 為 `null` 或 `simulation`，必須在圖上標明「未經文獻錨定」 |
| 二、模型階梯 | 橫條圖：M0／M1／M2／M3 之表現與信賴區間 | **M0 必須畫在最上面**，並以不同顏色標為「[洩漏基準](../05_%E6%A6%82%E5%BF%B5%E7%AD%86%E8%A8%98/%E6%B4%A9%E6%BC%8F%E5%9F%BA%E6%BA%96.md)線」；M2 未超過它時整張圖加警示框 |
| 三、排除試驗 | 敏感度固定下之陰性預測值、免除比例、漏掉人數 | 漏掉人數必須以絕對數字呈現，不得只給比例 |
| 四、可信度 | 本人之 N、可用配對數、旗標 | `estimable` 為 false 時，畫面一與三**不得顯示任何數字**，只顯示「資料不足以估計」 |

## 三之四　前端禁止事項

1. 不得對 `estimable: false` 的病人顯示推測值。
2. 不得顯示未經文獻錨定的參考指紋而不加標註。
3. 不得把 `posterior` 最大值呈現為「診斷」；措辭一律為「與此型態最相似」。
4. 不得隱藏 M0 或 gates 的結果。
5. 不得使用瀏覽器儲存 API 保存病人資料。

## 三之五　文字規範

| 不可寫 | 應寫 |
|---|---|
| 診斷為狼瘡腎炎 | 指紋與增生型免疫複合物型態最相似 |
| 排除狼瘡 | 於本模型設定下，狼瘡型態之相似度低 |
| 建議切片 | 供臨床判讀參考，切片與否由醫師決定 |
| 準確率 92% | 於本模擬設定下之相對比較（附設定摘要） |

# 第四部　驗收清單

## 階段一（生成器與閘門）

- [ ] 四道閘門各回報數值，非僅回報通過
- [ ] 純雜訊組回到隨機水準
- [ ] 逐人標準化輸入會拋出例外
- [ ] 單通道誤差放大不改變指紋
- [ ] 穩定病人被標記為不可估計，未被給值
- [ ] 同種子重跑逐位元相同

## 階段二（指紋核心）

- [ ] 在已知負載之合成資料上，公式二估計誤差 < 10%
- [ ] 對照組（用對角線變異數比）誤差顯著較大，兩者並列報告
- [ ] N 掃描表完整（8／12／20／34／60／120）
- [ ] R 之虛無分布表完整，且 N < 34 時標明不可用

## 階段三（模型比較）

- [ ] M0 先於 M2 定版，時間戳可稽核
- [ ] 四模型之表現與信賴區間齊備
- [ ] M2 − M0 之差異與信賴區間明確呈現
- [ ] 所有格點結果全數報告，失敗區域未刪除

## 階段四（前端）

- [ ] 四個畫面齊備且符合硬規則
- [ ] 未錨定之參考指紋皆有標註
- [ ] `estimable: false` 之病人不顯示數字
- [ ] 文字規範全數符合
- [ ] 單檔可直接開啟，無外部相依

## 附錄：現階段仍為 null 的參數

以下於 `etiologies.yaml` 中必須留 null 並於啟動時警告，不得填值：

| 參數 | 狀態 |
|---|---|
| ANCA 相關血管炎之負載向量 | 文獻未取得 |
| 糖尿病腎病變之負載向量 | 文獻未取得 |
| 各病因負載之相對幅度 | 現有文獻僅有高／中／低之定性描述 |
| 各通道之量測誤差大小 | 待 CGRD 重複檢驗變異估計 |
| T2 與 T3b 之可分性 | 本研究之主要待答問題，不得預設 |

有序位依據者（來自台灣腎切片註冊與 Fava 2024）可填入序位，但必須在 `source` 欄標明為 `literature_ordinal`，且模擬須對相對幅度做寬範圍掃描而非取單一值。
